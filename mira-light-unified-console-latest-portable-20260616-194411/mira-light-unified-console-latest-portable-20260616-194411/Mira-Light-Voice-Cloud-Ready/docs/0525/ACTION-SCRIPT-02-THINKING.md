# Mira Light 动作脚本 02：想 Thinking

参考视频：`0b5c990939c341f348ffc253b333e121-思考.mp4`  
目标用途：用户说完后，ASR/LLM 处理期间的等待动作  
核心要求：**不是低头卡住，而是“低头搜索 -> 停顿 -> 灵感抬起”的连续过程**

## 0. 当前问题

如果 Thinking 只写几个稀疏 pose：

```text
0.0 thinking start
0.7 turn down left
1.55 deeper left thought
...
```

真实台灯会表现成：

```text
咔 -> 停 -> 咔 -> 停
```

这不是“思考”，是“分段跳转”。Thinking 要有“慢动作中的细节”，尤其是：

```text
进入低头前先预备
低头后要有细微呼吸
左右搜索前要先回一点
灵感抬起不能一步到位
```

## 1. 经验姿态库

| 姿态 | P0 | P1 | P2 | P3 | 用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| `NATURAL` | 2048 | 2150 | 2048 | 2130 | 自然等待 |
| `THINK_FRONT` | 2048 | 2155 | 1930 | 2130 | 正面低头思考 |
| `THINK_LEFT` | 1940 | 2180 | 1880 | 1990 | 左侧低头 |
| `THINK_RIGHT` | 2160 | 2180 | 1880 | 2240 | 右侧低头 |
| `DEEP_PAUSE` | 2048 | 2185 | 1840 | 2130 | 深思停顿 |
| `IDEA_PREP` | 2048 | 2160 | 1980 | 2130 | 灵感前预备 |
| `IDEA_LIFT` | 2048 | 2240 | 2100 | 2130 | 想到了，抬起 |

说明：

- Thinking 的灵魂是 `P2` 低位/高位与 `P1` 的配合，不要孤立调某一个关节。
- `P3` 做歪头，表达“想不太确定”。
- `P0` 左右转要慢，不能像追踪目标。

## 2. 推荐速度

Thinking 要比 Listening 慢，但不能慢到卡死。

```text
进入低头:     --speeds 120 75 75 100
深思停顿:     --speeds 90 60 60 80
左右搜索:     --speeds 150 90 90 125
灵感抬起:     --speeds 220 135 135 160
收束准备答:   --speeds 160 95 95 125
```

## 3. 可直接落地的动作脚本

```python
THINKING_SCRIPT = [
    # 进入：先从自然态轻轻低头
    ("enter thought", 2048, 2150, 2000, 2130, (110, 75, 75, 95), 0.18),
    ("drop into front thought", 2048, 2165, 1930, 2130, (120, 80, 80, 100), 0.32),

    # 左侧搜索：不要直接去最深点
    ("prepare left thought", 2000, 2168, 1910, 2070, (130, 80, 80, 110), 0.16),
    ("left thought", 1940, 2180, 1870, 1990, (150, 90, 90, 125), 0.34),
    ("left breathe down", 1940, 2190, 1845, 2010, (85, 60, 60, 75), 0.28),
    ("left breathe up", 1970, 2170, 1900, 2040, (95, 65, 65, 85), 0.22),

    # 回中但不抬起，保持还在思考
    ("return low center", 2048, 2160, 1920, 2130, (125, 75, 75, 105), 0.26),
    ("front deep pause", 2048, 2185, 1840, 2130, (85, 60, 60, 80), 0.42),

    # 右侧搜索：先小反向，再主动作
    ("prepare right thought", 2090, 2168, 1910, 2190, (130, 80, 80, 110), 0.16),
    ("right thought", 2160, 2180, 1870, 2240, (150, 90, 90, 125), 0.34),
    ("right breathe down", 2160, 2190, 1845, 2220, (85, 60, 60, 75), 0.28),
    ("right breathe up", 2120, 2170, 1900, 2180, (95, 65, 65, 85), 0.22),

    # 灵感出现：必须两段抬起，不能一步到位
    ("idea prepare", 2048, 2160, 1980, 2130, (120, 75, 75, 100), 0.16),
    ("idea lift half", 2048, 2200, 2040, 2130, (180, 110, 110, 140), 0.14),
    ("idea lift full", 2048, 2240, 2100, 2130, (230, 140, 140, 170), 0.22),
    ("idea small rebound", 2048, 2190, 2020, 2130, (120, 80, 80, 100), 0.18),

    # 准备回答：回正但保留一点上扬
    ("ready to answer", 2048, 2160, 2020, 2130, (150, 90, 90, 120), 0.24),
]
```

## 4. 可变时长设计

Thinking 必须适配 LLM 延迟，不应固定死 9 秒。

建议拆成：

```text
entry:  enter thought -> drop into front thought
loop:   left search -> center pause -> right search -> center pause
exit:   idea prepare -> idea lift -> ready to answer
```

如果 LLM 很快：

```text
entry 后直接 exit
```

如果 LLM 慢：

```text
重复 loop，但每次左右幅度略微变化 10-20 units，避免机械重复
```

## 5. 避免卡顿的具体规则

### 不要这样

```python
(0.00, pose_front)
(0.70, pose_left)
(1.55, pose_deep_left)
```

### 要这样

```text
front -> prepare_left -> left -> left_breathe_down -> left_breathe_up
```

每个“思考点”至少 3 个姿态：

```text
进入点
主点
呼吸回弹点
```

## 6. 调参规则

如果不够灵动：

```text
P3 增加 30-70 units 歪头
每个低头点加一个 breathe up/down
左右搜索前加 prepare pose
```

如果还是一卡一卡：

```text
缩短单段 hold 到 0.12-0.28
增加过渡 pose
降低 P1/P2 speed
不要让相邻 pose 差值超过 120-160
```

如果太慢：

```text
只提高 P0/P3 speed
P1/P2 不要同时大幅加速
```

## 7. 灯光脚本建议

```text
进入思考: 暖白 60
深思: 暖白 45-55，慢呼吸
灵感: 暖白升到 110
准备回答: 稳定 100
```

不要在 thinking 用彩色灯。彩色会让它像庆祝，不像思考。

## 8. 验收标准

- 低头不是瞬间砸下去。
- 左右搜索有准备、有回弹。
- 至少有一处明确停顿，但停顿不是死机。
- 灵感抬起是两段式，不是一步跳到高点。
- 可根据 LLM 延迟循环，不露馅。
