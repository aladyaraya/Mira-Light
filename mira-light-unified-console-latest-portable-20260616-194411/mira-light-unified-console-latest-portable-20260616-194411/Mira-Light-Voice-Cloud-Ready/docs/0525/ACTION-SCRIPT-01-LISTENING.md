# Mira Light 动作脚本 01：听 Listening

参考视频：`0df6af9bf4b0303177c7b607efc3e988-听.mp4`  
目标用途：用户说话 / ASR 录音 / Mira 等待输入时的持续倾听动作  
核心要求：**不能一步到位，必须用连续小段做“活着的注意力”**

## 0. 先纠正一个关键点

这台 Mira Light 不能按“单关节语义表”粗暴设计动作。

实际动作要按下面这种思路写：

```text
pose0 = 进入姿态
sleep 0.10-0.25
pose1 = 小幅预备
sleep 0.08-0.18
pose2 = 主表达
sleep 0.12-0.28
pose3 = 回弹 / 呼吸
```

如果只写：

```text
0.00 pose A
0.55 pose B
1.10 pose C
```

它看起来就会一卡一卡。真实台灯要靠“预备、主动作、回弹、停住”组成一个动作簇。

## 1. 真实关节使用规则

命令格式：

```bash
python3 /home/sunrise/Desktop/four_servo_control.py pose P0 P1 P2 P3 --speeds S0 S1 S2 S3
```

当前项目里可靠的经验姿态：

| 姿态 | P0 | P1 | P2 | P3 | 用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| `NEUTRAL` | 2048 | 2150 | 2048 | 2130 | 自然等待位，不是全 2048 |
| `SOFT_FRONT` | 2048 | 2140 | 1980 | 2130 | 正面轻低头，适合听 |
| `ATTEND_LOW` | 2048 | 2160 | 1920 | 2130 | 更专注地低头听 |
| `LEFT_ATTEND` | 1980 | 2150 | 1960 | 2060 | 向一侧倾听 |
| `RIGHT_ATTEND` | 2120 | 2150 | 1960 | 2200 | 向另一侧倾听 |
| `ACK_UP` | 2048 | 2180 | 2060 | 2130 | 轻轻抬起，表示“我听到了” |

注意：

- `P0` 是底座/身体方向，用来左右找人。
- `P1` 和 `P2` 是联动决定灯臂高度和灯头朝向，不能孤立解释。
- `P3` 是头部/末端歪头，最适合做“灵动”和“微表情”。
- `2048 2048 2048 2048` 不是最佳自然态；现场自然态通常更接近 `2048 2150 2048 2130`。

## 2. 设计目标

“听”不是回答，不要太兴奋。它应该像：

```text
我在听
我捕捉到重点
我稍微确认了一下
我继续安静等你说完
```

动作重点：

- 小幅左右注意力漂移。
- 低头靠近，而不是大幅抬头。
- 每次方向变化之前有一个很短的中间过渡。
- 每 1.2-1.8 秒给一次细小回应，不要连续摇。

## 3. 推荐基础速度

Listening 要轻、快、不断裂。

```text
慢速进入:      --speeds 140 90 90 120
小幅听觉摆动:  --speeds 180 110 110 150
微点头/确认:   --speeds 220 130 130 170
回弹/收束:     --speeds 120 80 80 100
```

不要用所有关节同一个 speed。`P1/P2` 负载大，通常应比 `P0/P3` 慢。

## 4. 可直接落地的动作脚本

这是推荐替换当前稀疏 timeline 的脚本结构。

```python
LISTENING_SCRIPT = [
    # 进入：不要从中性瞬间跳到听，要先软落下
    ("enter soft front", 2048, 2140, 2000, 2130, (130, 85, 85, 110), 0.16),
    ("settle into listening", 2048, 2155, 1960, 2130, (120, 75, 80, 100), 0.22),

    # 左侧捕捉：三段式，不一步到位
    ("prepare left", 2020, 2150, 1970, 2100, (150, 85, 85, 120), 0.10),
    ("listen left", 1975, 2160, 1940, 2055, (185, 105, 105, 150), 0.26),
    ("left micro rebound", 2005, 2150, 1975, 2085, (135, 80, 80, 110), 0.16),

    # 回中 + 轻点头确认
    ("return center low", 2048, 2155, 1950, 2130, (145, 85, 85, 120), 0.14),
    ("tiny nod down", 2048, 2160, 1905, 2130, (160, 95, 95, 120), 0.12),
    ("nod rebound", 2048, 2145, 1990, 2130, (130, 75, 75, 100), 0.20),

    # 右侧捕捉：同样三段式
    ("prepare right", 2075, 2150, 1970, 2160, (150, 85, 85, 120), 0.10),
    ("listen right", 2120, 2160, 1940, 2200, (185, 105, 105, 150), 0.26),
    ("right micro rebound", 2085, 2150, 1975, 2170, (135, 80, 80, 110), 0.16),

    # “我听到了”的轻抬，不要变成回答
    ("ack prepare", 2048, 2160, 2000, 2130, (140, 85, 85, 110), 0.10),
    ("ack up", 2048, 2190, 2070, 2130, (190, 120, 120, 140), 0.18),
    ("ack settle", 2048, 2150, 1985, 2130, (125, 80, 80, 100), 0.28),

    # 收尾：回到可循环起点
    ("calm front", 2048, 2140, 2000, 2130, (110, 75, 75, 90), 0.30),
]
```

执行生成示例：

```python
for label, p0, p1, p2, p3, speeds, hold in LISTENING_SCRIPT:
    s0, s1, s2, s3 = speeds
    print(label, [p0, p1, p2, p3])
    subprocess.Popen([
        "python3", "/home/sunrise/Desktop/four_servo_control.py",
        "pose", str(p0), str(p1), str(p2), str(p3),
        "--speeds", str(s0), str(s1), str(s2), str(s3),
    ])
    time.sleep(hold)
```

## 5. 为什么这版不会卡

每个方向变化都拆成：

```text
prepare -> main -> rebound
```

比如左听：

```text
2048/2155/1960/2130
-> 2020/2150/1970/2100
-> 1975/2160/1940/2055
-> 2005/2150/1975/2085
```

这样身体不是突然“啪”到左边，而是有惯性。

## 6. 调参规则

如果仍然卡：

```text
1. 增加中间 prepare pose
2. 降低 P1/P2 speed 10-20%
3. 每个主动作后加 0.10-0.16s rebound
```

如果不够灵动：

```text
1. 增加 P3 微歪头 ±30-60
2. 在主动作前加 0.08s 反向预备
3. P0 小幅摆动，不要超过 ±120
```

如果太像回答：

```text
1. 降低 ACK_UP 的 P1/P2
2. 减少抬头次数
3. 延长低头停留
```

## 7. 验收标准

- 不能看到明显一帧一帧跳。
- 左右听的动作有“走过去”和“回弹”。
- 整段可以循环，用户说 20 秒也不烦。
- 不出现大幅庆祝、强点头、强抬头。
- 结束能自然接入“想”状态。
